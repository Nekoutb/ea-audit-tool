AuditISA · reconciliation plan · 8 August 2026

Bringing the 36 designed papers and the
66 platform tasks into one inventory

The console proposal names 36 working papers. The platform carries 66 tasks under its own codes. They overlap heavily but were never reconciled. This is the mapping, task by task, and what it would take to act on it.

27designed papers that map onto an existing task
6that have no counterpart and must be added
3that split across several existing tasks
36platform tasks the design never named — all kept
The headline: this is a merge, not a replacement. The platform is richer than the design in execution and statutory work — it has a task per account cycle and the full OHADA set, where the design has one generic “substantive procedures” paper. The design is richer in acceptance, where the platform has two tasks against seven. Reconciling means adopting the design’s content onto the platform’s structure, and adding the six papers genuinely missing.

05

The work, in order

each step shippable on its own

  1. Add the six missing tasks

    ACC-3 independence, ACC-4 preconditions, ACC-6 engagement letter, ACC-7 review determination, PLN-7 significant classes of transactions, CON-8 auditor’s report, CON-11 other information. New codes in the file index, placed in their groups, with their gate conditions. Acceptance goes 2 → 7.

    Migration: file_item rows for existing engagements need backfilling, using the same idempotent button already built for the E2 group.

  2. Retitle and re-home the misplaced

    D5.2 becomes account scoping rather than commitments and contingencies. Going concern conclusion moves from Execution to Conclusion, or gains a cross-reference. B1 splits into final analytics and sufficiency.

    Retitling is safe; moving a task between phases changes which gate it blocks — check the gate queries first.

  3. Port the paper content

    Replace the group-derived defaults in lib/working-papers.ts with the real content: procedures with expected sources, Yes/No factor checklists with per-question explanation boxes, the standards narrative, the definitions table. Roughly 43,000 words already written and register-checked.

    Largest single step. Do it phase by phase — acceptance first, since it is the weakest.

  4. Merge the two template systems

    One definition per task drives both the on-screen paper and the .docx export, replacing the three real templates plus generic stub in lib/templates.ts and the parallel structure in lib/working-papers.ts.

    Documents already generated are frozen by design; the merge must not invalidate them.

  5. Wire the tool values into the papers

    The blue fields currently show a source hint. Feed them the real numbers: materiality into ACC/PLN-5, the account universe and significance into PLN-6, what-can-go-wrong into PLN-7, the strategy into PLN-9, the misstatement totals into CON-4.

  6. Extend the gates

    The new papers need gate conditions: G1 does not clear without independence, preconditions and the letter; G2 not without SCOT understanding; G5 not without other information and the report paper.

    Adding a gate condition can block an engagement mid-flight. Ship with the condition reporting but not blocking, then switch it on.

Decisions I need from you

QuestionMy recommendation
Keep the platform’s 36 unnamed tasks, or trim to the design’s 36?Keep. The account cycle tasks and the OHADA statutory set are what make this usable in Cameroon. Trimming would lose them.
Renumber to the ACC/PLN/EXE/CON scheme, or keep D/E/A/B/C/F codes?Keep the internal codes, show the display codes. The ST/E/C display layer already does this; renumbering the storage keys would break every document and sign-off.
Should going concern be one paper or two (planning and conclusion)?Two. The standard treats them as separate judgements at separate dates, and the platform already has D5.5 and E330.
Do the new gate conditions block immediately?No. Report first, block a period later, so no live engagement is stranded.
Which phase first?Acceptance. Two tasks against seven is the gap an inspector would find first.
