05 Engagement lifecycle & the gates between phases

An engagement is a state machine. It cannot skip a phase, and each transition is a single locked transaction that checks its gates and mutates the phase together — no half-advances, no races. These are the real conditions the code enforces.

  • D3.1 form complete & conclusion = accept
  • D3.1 partner-signed (on the workpaper)
  • Independence complete — campaign exists, every confirmation returned
  • Exceptions disposed — no undisposed independence exception
Planning → Execution
  • Materiality approved (latest version)
  • D6.1, D7.1, D7.2 partner-signed
  • Significant risks linked — each non-rebutted significant risk has ≥1 program step
  • Rebuttals approved
  • Stand-back — every material section covered by a step

Execution → Conclusion
  • All sections concluded, no step left planned
  • All risks concluded; late risks approved

  • Sets archived_at — the file becomes immutable (documents can no longer be checked out or edited)

06 Document sign-off engine

Every working paper carries its own approval state. This is the two-stage minimum (preparer, then reviewer/partner) that underpins the whole audit trail. A reviewer sign-off locks the paper; reopening voids the sign-offs and notifies the signers.

%%{init: {'theme':'base','themeVariables':{'fontFamily':'system-ui','primaryColor':'#eef2f4','primaryTextColor':'#191c21','primaryBorderColor':'#0c7a58','lineColor':'#565d68','fontSize':'13px'}}}%%
stateDiagram-v2
  direction LR
  [*] --> draft: generateDocument()
  draft --> draft: check-out / check-in\n(new immutable version)
  draft --> preparer_signed: sign(preparer)
  preparer_signed --> signed: sign(reviewer / partner)
  signed --> draft: reopen(reason)\nvoids sign-offs
  signed --> [*]: locked
  note right of preparer_signed : blocked if any\nreview note is open
  note right of signed : status = 'signed'\nLOCKED
🔒 The rules the engine enforces
  • preparer-first — reviewer/partner cannot sign before the preparer
  • open-notes — an open review note blocks all higher sign-offs
  • signed-locked — a signed paper is read-only until reopened
  • checked-out — must be checked in before signing
  • already-signed — one active sign-off per role
  • role authority — reviewer needs ≥ senior, partner needs ≥ partner
🧾 What's permanent
  • Bytes live in immutable document_version rows — history is never rewritten
  • restoreVersion copies an old version forward as a new one
  • Each version is sha256-hashed; the template used is stamped into the version note
  • Reopen records a reason and voids sign-offs with an audit stamp
"Save & hand off" on a task page runs this whole chain in one click: save fields → generate the document if needed → sign as preparer → record activity → return to the group.

08 Multi-tenancy & security

Isolation is enforced by the database, not by application code remembering to filter — the safest possible default.

Row-Level Security (fail-closed)

Every query runs inside withTenant(), which sets a transaction-local app.tenant_id. Each table has FORCE ROW LEVEL SECURITY with a policy that only matches that id.

If the context is ever unset, the comparison is NULL and no rows are visible — the table fails closed rather than leaking.

Least privilege

The app connects as a non-owner role (ea_app) because owners/superusers bypass RLS.

tenant, app_user and membership sit outside RLS — they're read during authentication, before a tenant context exists, and are scoped by user id in code.
